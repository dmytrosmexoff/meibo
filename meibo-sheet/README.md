# 利用者名簿 на Umbrel + MySQL

Внутри: сайт (`app/web/index.html`), серверная часть на PHP (`app/web/api.php`), MySQL 8.4 в отдельном контейнере.
Доступ защищён дважды: входом Umbrel и **аккаунтами внутри приложения** (см. раздел «Аккаунты»). Одновременно работать могут несколько устройств: изменения общие и подтягиваются сами примерно раз в 20 секунд.

## Что понадобится
- Интернет на сервере **во время установки** (Umbrel скачает `php:8.3-apache` и `mysql:8.4`, соберёт образ сайта и добавит магазин из Git). Первая установка занимает несколько минут. После этого сервер может работать без интернета.
- Репозиторий Git (например, на GitHub), куда вы загрузите содержимое этой папки.

## Установка
1. Создайте репозиторий и загрузите в него **содержимое папки `umbrel-meibo-store`** так, чтобы в корне репозитория лежали файл `umbrel-app-store.yml` и папка `meibo-sheet`.
2. В Umbrel: App Store → меню «⋯» → Community App Stores → добавьте адрес репозитория.
3. Найдите приложение «利用者名簿» и нажмите «Установить». Ничего собирать вручную по SSH не нужно: образ сайта Umbrel соберёт сам при установке.
4. Приложение открывается на порту **1475** через Umbrel.

### Если установка упала с «Command failed with exit code 1 ... app-script install meibo-sheet»
Причина (версии 1.0.1): путь сборки был относительным (`build: ./app`), а Umbrel запускает сборку не из папки приложения, поэтому не находил `Dockerfile`. В версии 1.0.2 путь абсолютный (`${APP_DATA_DIR}/app`), это тот же приём, который проверен на реальном umbrelOS другими авторами приложений.
Если после обновления всё равно ошибка: на сервере выполните `ls ~/umbrel/app-data/meibo-sheet/` (должна быть папка `app`) и пришлите последние строки журнала (Настройки → Дополнительно → Устранение неполадок → umbrelOS logs).

### Если установка упала с ошибкой «pull access denied for meibo-web»
Так было в предыдущей версии: она ждала готовый образ `meibo-web`, а его нет в интернете. В этой версии это исправлено (образ собирается при установке). Что сделать:
1. Удалите неудавшуюся установку приложения (если Umbrel показывает его как установленное).
2. Загрузите новую версию файлов в репозиторий (версия приложения 1.0.1).
3. В Umbrel обновите магазин сообщества (удалите его и добавьте снова, если не обновился) и установите приложение заново.

## Первый запуск
Встроенная база данных создаётся самим приложением (как раньше), настраивать её не нужно. При первом открытии появится окно регистрации: **первый зарегистрированный аккаунт становится администратором**, остальные ждут его подтверждения.

## Формы A4: 水分チェック表 и 排泄チェック表
В левой панели блок «フォームA4（水分・排泄）»: укажите количество дней и нажмите одну из двух кнопок.
- Страница 1 — выбранный день, страница 2 — следующий, страница 3 — послезавтра и так далее. Каждый день — отдельный лист A4 альбомной ориентации.
- Для двусторонней печати: один лист A4 = два дня (лицевая сторона — первый день, оборотная — следующий). Включите в окне печати «двусторонняя печать, переворот по длинной стороне».
- Имена берутся из листа этого дня в том же порядке (сначала ночующие, затем приходящие, затем выездные), в конце 4 пустые строки для ручной записи. Для дней без сохранённого листа список строится по обычному шаблону этого дня недели (★).
- Дата выводится автоматически. Колонки 小計 и 合計 пустые.
- Печать — через окно печати браузера: выберите «Сохранить как PDF» или печать на принтере (Chrome или Edge).

## Загрузка готовой базы и копирование
- **При первом запуске** (пока нет ни одного аккаунта) над формой регистрации есть необязательное поле «Загрузить базу (.sql)». Файл — экспорт базы (например, mysqldump). Он загружается во встроенную базу, после чего регистрируетесь как обычно. Загрузка возможна только до регистрации первого аккаунта. Пустые таблицы, созданные приложением при запуске, заменяются таблицами из файла (данные, введённые до регистрации, при этом теряются). Размер до 64 МБ. Регистрируйтесь сразу после установки, чтобы никто посторонний не успел загрузить файл.
- **Администратор** → «База данных» → при подключённой второй базе: **«Встроенная → подключённая»** или **«Подключённая → встроенная»**. Копирование полностью заменяет данные в той базе, куда копируем (кнопка требует подтверждения вторым нажатием). Копируются люди, листы, сотрудники, аккаунты, комментарии, история. Настройки подключения и сессии не копируются. После копирования в направлении «подключённая → встроенная» аккаунты заменяются на аккаунты второй базы, и текущий вход может слететь: войдите снова.

## Порядок людей, номер листа, ширина
- Над списком людей три стрелки **▲ 通い, ▲ 泊まり, ▲ 訪問**. Нажатие поднимает наверх всех, кто на сегодня отмечен этим пунктом (порядок внутри группы сохраняется). Остальные идут ниже в прежнем порядке.
- В шапке листа и в блоке справа номер листа теперь задаётся вручную: поле «番号» и кнопка «設定» рядом с датой. Если лист уже сохранён, его номер меняется, а следующий новый лист получает номер после него (1→2→3→4→1). Если листа ещё нет, его первое сохранение получит указанный номер.
- Колонка 注意点 растёт, когда в заметках длинный текст: остальные колонки сжимаются, лист по-прежнему занимает всю ширину A3.
- Между последним дневным сотрудником (日勤) и блоком 夜勤 оставлены две пустые строки.

## Печать и шрифт
- Шрифт MeiboJP (японские иероглифы) поставляется вместе с приложением, файл `meibo-jp.woff`. Интернет для него не нужен.
- Лист печатается без масштабирования через трансформацию: при нехватке места уменьшение делается через `zoom`, текст остаётся векторным и не размывается.
- Линии сетки стали толще (0,7 pt), чтобы не пропадали на принтерах.
- Страница администратора (`admin.html`) пересобрана из той же версии, что и лист.

## PDF-бланки (水分表 и 排泄表)
Кнопки **PDF 水分** и **PDF 排泄** рядом с печатью форм скачивают PDF. Бланк строится по образцам (`app/forms/水分表.xlsx`, `排泄表.xlsx`), имена в бланках не заполняются (строки остаются для записи от руки):
- одна книга, на каждый день свой лист (название листа — дата), каждый лист печатается на одну страницу A4 альбомно; в двустороннем режиме лист 1 и лист 2 идут на одном бумажном листе;
- имена — только **通い и 泊まり** на этот день (выездные в бланк не попадают);
- в конце **5 пустых мест** для ручной записи (если людей много, пустых мест меньше не становится);
- дата и день недели выводятся автоматически.
Для сборки PDF на сервере ставятся Python 3, openpyxl, LibreOffice и японские шрифты (Dockerfile). Образ станет больше, первая сборка займёт дольше.

## Лист: один лист A3 всегда
Высота строк и нижних полей (кроме строки с датой) подстраивается под число людей, чтобы лист всегда помещался на одну страницу A3. Сначала уменьшаются пустые строки и поля внизу, затем высота строк людей (не ниже 5.2 мм), и только для очень большого числа людей включается небольшое уменьшение всего листа целиком. Строка с датой не уменьшается никогда.

## Лекарства и колонки
- 服薬 печатается простым текстом (иероглифами), без цветных кружков.
- 臨薬 (抗生物質) сужается до узкой вертикальной колонки, когда в этот день никому не нужен; с галочкой у кого-то снова становится обычным.
- 整容 стала у́же.
- Внизу листа число 通い и 泊まり подставляется само по числу отмеченных людей. Число людей на завтрак/обед/ужин пишется в скобках рядом с названием приёма пищи, например «朝食(5)　　　名».

## Выездные (訪問): всё в одном окне
Отдельного списка питания под именем больше нет. У выездного человека еда, доставка, лекарства и заметка настраиваются в том же окне ✎, что и у остальных (кнопка-карандаш).

## Страница администратора (отдельная, не всплывающее окно)
Кнопка «Админка» и 7 нажатий на заголовок теперь открывают отдельную страницу `admin.html`, а не окно поверх листа. Доступна только администратору. Вкладки: Статистика, **Люди** (новая), Аккаунты, Комментарии, База данных.
Вкладка «Люди»: список всех людей с их порядковым номером в списке и на листе. Номер можно вписать вручную или сдвинуть стрелками ↑ ↓, это сразу меняет порядок на листе. Кнопка «Настройки» у каждого открывает тот же редактор, что и ✎ на обычном листе: имя, тип (通い/泊まり или 訪問), еда, еда для выездных, доставка, лекарства, заметка.

## Две базы данных: встроенная и ручное подключение
Приложение может работать сразу с двумя базами MySQL:
- **Встроенная** создаётся приложением и работает всегда.
- **Ручное подключение** (вторая база, например на другом сервере) вводится администратором: «Админка» → «База данных» → хост, порт, имя базы, логин, пароль → **«Проверить подключение»** → **«Подключить и синхронизировать»**. Если базы нет и у логина есть права, она будет создана. Отключить можно кнопкой «Отключить», вернуть связь можно в любой момент.
- **Синхронизация в обе стороны, побеждает самая новая информация:** для каждой записи (человек, лист за день, список сотрудников, аккаунт, комментарий) сравнивается время последнего изменения, и более свежая копия переписывает более старую в другой базе. Записи, которых нет с одной стороны, копируются туда. Удаления (человек, аккаунт, комментарий) тоже переносятся и обратно не воскресают. Копируется и история изменений листов и людей.
- Автоматически синхронизация идёт каждые 2 минуты (запускает любой открытый экран), кнопка «Синхронизировать сейчас» запускает её вручную и показывает, сколько записей ушло в каждую сторону. Если вторая база недоступна, приложение продолжает работать со встроенной, а ошибка видна в окне администратора. Связь с обеими базами и время последнего изменения видны там же.
- Что не копируется: журнал отдельных правок (`log`), входы в систему (после смены базы войти придётся заново) и счётчики попыток входа. Пароль второй базы хранится во встроенной базе.
- Важно: время изменения берётся с сервера приложения. Если у приложения на двух серверах часы сильно расходятся, «самая новая» запись может определиться неверно. Держите время на серверах правильным.
Администратор может проверить связь с базами в любой момент: «Админка» → «База данных».

## Работа без связи с базой
Если сервер или база недоступны, вверху появляется жёлтое предупреждение (окон и ссылок на настройку нет). Все правки сохраняются в браузере этого компьютера и отправляются в базу сами, как только связь вернётся, даже если закрыть вкладку. Если очистить данные браузера до отправки, неотправленные правки пропадут. При выходе из аккаунта копия в браузере удаляется, если всё уже отправлено.

## Проверка
Администратор может проверить связь с базой в любой момент: «Админка» → «База данных» → «Проверить подключение к базе данных».
Откройте `http://umbrel.local:1475/check.php` (Umbrel попросит вход). Ожидается `ALL GOOD` и версия MySQL.
Если там `ERROR`, скопируйте строку целиком: по ней видно причину (чаще всего MySQL ещё запускается, подождите минуту и обновите страницу).

## Проверка без Umbrel (по желанию)
На любом компьютере с Docker, в папке `meibo-sheet`:
```
docker compose -f docker-compose.standalone.yml up -d --build
```
Откройте `http://АДРЕС:1475/check.php` (должно быть `ALL GOOD`) и `http://АДРЕС:1475/`. В этом режиме входа нет, используйте только в закрытой сети. Остановить: `docker compose -f docker-compose.standalone.yml down`.

## Резервная копия
Раз в сутки (например, через cron на сервере):
```
docker exec meibo-sheet_db_1 sh -c 'mysqldump -umeibo -p"$MYSQL_PASSWORD" meibo' > /путь/к/диску/meibo-$(date +%F).sql
```
Хранить на отдельном диске и раз в месяц проверять, что копия восстанавливается:
`docker exec -i meibo-sheet_db_1 sh -c 'mysql -umeibo -p"$MYSQL_PASSWORD" meibo' < meibo-ДАТА.sql`
Данные базы лежат в `~/umbrel/app-data/meibo-sheet/data/mysql`. При удалении приложения из Umbrel они могут пропасть: сначала сделайте копию.

## Аккаунты и права
- Без входа страница ничего не показывает. Окно входа и регистрации открывается первым.
- **Первый зарегистрированный аккаунт становится администратором** и сразу активен. Поэтому зарегистрируйтесь сами первым, сразу после установки.
- Все остальные после регистрации ждут: администратор один раз подтверждает доступ (окно администратора: быстро нажмите 7 раз на заголовок «利用者名簿», вкладка «Аккаунты», кнопка «Подтвердить»). Там же можно остановить или удалить аккаунт. Окно администратора на русском языке (вкладки: Статистика, Аккаунты, Комментарии, База данных). Открыть его можно кнопкой «Админка» внизу экрана (рядом с «コメント»): её видит только администратор, у обычных пользователей кнопки нет. В скобках на кнопке число заявок, ожидающих подтверждения.
- Вход не заканчивается по времени: из аккаунта автоматически не выкидывает (только кнопка «ログアウト»).
- Обычный пользователь видит и редактирует всё, что есть на листе (люди, лекарства, смены, печать). Статистика, список аккаунтов и скрытая страница базы доступны только администратору. Это ограничение интерфейса: данные листов пользователь видит сам, поэтому сводки по ним он теоретически может посчитать вручную.
- Пароль: от 8 знаков. После 8 неверных попыток вход на аккаунт закрывается на 10 минут.

## Комментарии разработчику
Кнопка «コメント» внизу слева. Любой пользователь может написать комментарий, но прочитать (свои и чужие) не может. Читает и удаляет их только администратор: окно администратора → «Комментарии».

## Печать нескольких дней одним PDF
В левой панели раздел «印刷キュー»: кнопка «キューに追加» добавляет выбранный день в очередь (и сохраняет его). В очередь помещается до 15 дней. «まとめてPDF保存» собирает все дни из очереди в один файл (по странице A3 на день, в окне печати выберите «Сохранить как PDF»). Очередь хранится в этом браузере.

## Редкие лекарства 臨薬 (抗生物質)
По умолчанию в 臨薬 пусто. В настройках человека (✎) есть галочка «臨薬: 抗生物質»: пока она стоит, у этого человека в листе печатается слово «抗生物質» простым текстом, без рамки.

## История
Ничего не стирается: каждое сохранение дня и каждая правка человека записываются новой строкой, старые версии остаются.
- `days_history`: все версии листа за каждую дату (когда сохранено, кто пришёл, смены, цифра листа).
- `people_history`: все версии человека (и последняя копия с пометкой «удалён»).
- `log`: каждая отдельная правка (что было и что стало).
Читаемые таблицы для просмотра: `attendance` (кто пришёл и когда, с именем), `staff_days` (кто работал в смену), `person_settings` (настройки каждого человека по датам), `person_absence` (периоды отсутствия).
Примеры запросов лежат внизу `schema.sql`. Смотреть базу можно через терминал Umbrel:
`sudo docker exec -it meibo-sheet_db_1 sh -c 'mysql -umeibo -p"$MYSQL_PASSWORD" meibo'`, затем например `SELECT * FROM attendance;`
Важно: в обычных программах для баз данных этот MySQL не виден (он закрыт от сети намеренно), только через терминал.

## Страница просмотра базы (скрытая, только для администратора, с отдельным паролем)
Откуда открыть: войдите администратором, быстро нажмите **7 раз** на заголовок «利用者名簿», в окне администратора откройте вкладку «База данных» и нажмите ссылку. Обычному пользователю этой ссылки не видно.
Адрес страницы вида `http://umbrel.local:1475/kanri.php?k=...` видно и в `check.php` в строке «Admin page». Без правильного `k=...` в адресе страница отвечает «Not Found», как будто её нет. Ключ в адресе уникален для вашей установки (получается из секрета Umbrel), в репозитории его нет.
При первом открытии страница просит **придумать пароль** (от 8 знаков). Потом вход только по этому паролю. После 5 неверных попыток вход закрывается на 10 минут. Вход действует 2 часа.
Что можно: смотреть все таблицы, листать по 50 строк, искать по тексту, скачать таблицу в CSV. Изменять данные нельзя (только чтение). Если забыли пароль, в терминале Umbrel: `sudo docker exec meibo-sheet_db_1 sh -c 'mysql -umeibo -p"$MYSQL_PASSWORD" meibo -e "DELETE FROM admin_settings"'`, и страница снова предложит создать пароль.

## Таблицы
`people` (человек и все версии его настроек), `days` (лист за дату и его цифра 1→4), `attendance` (кто пришёл и кто ночевал, удобно для SQL-отчётов), `staff` (список сотрудников), `log` (журнал изменений), `meta` (счётчик листов).
Пример отчёта: в `schema.sql` внизу.

## Как это работает
- Изменения отправляются на сервер через 0.4 с после правки. Если связь пропала, наверху появляется жёлтая надпись, а правки отправятся сами, когда связь вернётся.
- Если два человека одновременно правят одно и то же, побеждает тот, кто сохранил первым, второй получает сообщение и свежие данные.
- Цифру листа (1, 2, 3, 4, 1…) выдаёт сервер одной операцией при первом сохранении дня, поэтому два устройства не получат одинаковую.
- Данные из версии «файл в браузере» сюда автоматически не переносятся (список людей придётся ввести заново).
